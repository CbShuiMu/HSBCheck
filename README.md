# HSB Check

JavaScript + React + Vite 纯前端 HSBC 信用卡 PDF 结单整理工具。红白配色沿用原有设计；已将账户 ID / 银行 API 查询替换为本地 PDF 导入，不需要网银授权或后端。

## Cloudflare 部署

生产域名：<https://pulse.cbshuimu.net>。源码保存在 GitHub 私有仓库 `CbShuiMu/HSBCheck`，首次静态资源部署和自定义域名绑定已完成。

自动部署：Cloudflare Workers Builds 已连接此私有仓库并跟踪 `main` 分支。推送到 `main` 会自动运行测试、构建并发布到生产域名。构建令牌保存在 Cloudflare 中，不写入源码。配置如下：

- Node.js 22.22.0，依赖使用 `npm ci` 安装。
- 构建命令：`npm test && npm run build`。
- 部署命令：`npx wrangler deploy`。
- Worker 名称：`hsb-check`，静态资源目录：`dist/`，域名由 `wrangler.jsonc` 管理。
- 使用 Workers 静态资源托管，不需要数据库或付费后端；PDF 和密码仍在浏览器内处理。
- 本地手动部署可在完成 Cloudflare CLI 登录后运行 `npm run deploy`。不要将 API Token 写入仓库。

## 本地运行

需要 Node.js 22.12+（推荐）或 20.19+，以及支持 Web Worker、Web Crypto 的现代浏览器。

```bash
npm install
npm run dev
```

打开终端中的本地地址。生产构建运行 `npm run build`，将 `dist/` 整个目录部署到静态托管；`npm run preview` 预览生产包。开发与预览服务器只提供静态资源，不接收或解析结单文件。localhost 或 HTTPS 环境用于浏览器本地文件指纹计算。

## 使用

1. 将一份或多份 PDF 拖入页面，或点击“选择 PDF 结单”。也可以继续追加导入。
2. 每个文件逐页解析，显示交易数量和结欠核对状态。某份失败不影响其他文件。
3. 密码保护的 PDF 会提示解锁；在文件列表点击“输入密码”，错误密码可重试。
4. 搜索商户或交易说明，按收支、日期、币种、交易类型、来源结单及子账户筛选。
5. 点击每行右侧箭头查看交易日、入账日、原始文字及来源页码，支持打开原 PDF 对应页。
6. 导出当前筛选的全部交易及来源为 CSV。移除文件会重新计算汇总；刷新或清除会移除页面内数据。

## 今年返现

交易概览上方显示基础返现、赏世界 5x、PULSE 专属内地奖赏，**全部以人民币显示**。仅计算香港时间本年 1 月 1 日至今天已入账的导入记录，年度返现不受下方交易筛选影响。

待确认交易继续显示在明细中，但不计入任何返现，也不占用两项年度消费额度；待确认退款同样暂不扣回返现。支付方式无法识别的记录须在详情确认后才计入；交易本身尚未入账时，手动修改支付方式也不会提前计入。因此相邻结单中的待确认记录不贡献返现，仅已确认记录参与计算。

- 基础：人民币和港币净消费的 0.4%，无上限；港币部分用公开 HKD/CNY 参考汇率折算成人民币。还款、费用、奖赏入账本身不计消费。
- 赏世界 5x：人民币消费额外 2%，独立年度消费额度 CNY 80,000。
- PULSE 专属：有 Apple Pay / UnionPay QR 标记的人民币消费额外 2%，独立年度消费额度 CNY 80,000。
- 普通 Tenpay / Alipay / UnionPay 为封顶前 2.4%；Apple Pay / 明确银联 QR 为封顶前 4.4%。普通 `UNIONPAY MERCHANT` 不自动当作 QR。
- 两个进度条按**退款前的累计消费**占用额度，退款不会恢复额度。各项额外返现按 `min(累计合资格消费, 80000) × 2% - 对应渠道退款 × 2%` 估算，最低为 0。基础按退款后的净消费计算。
- 退款无法可靠关联原消费时会提示核对，可在交易详情手动确认支付方式；若退款对应的原消费已超额且未获额外奖赏，可勾选“仅扣基础返现”。专属渠道退款会扣回两项额外奖赏，普通渠道退款只扣回赏世界奖赏。
- 手动修正仅存在页面内存中，立即更新年度卡片；刷新或清除后重置。缺少月份、无法识别的渠道、跨年退款和银行取整方式可能影响估算，最终以银行实发为准。

汇率使用 [Frankfurter 公开日参考汇率 API](https://frankfurter.dev/)：`GET https://api.frankfurter.dev/v2/rate/HKD/CNY`，界面显示汇率日期并支持刷新。请求不含账户、交易、PDF、Cookie 或授权信息。失败不使用虚构汇率；没有可用汇率时港币部分暂不折算，人民币奖赏及额度继续计算。刷新失败且已有汇率时，会明确标注沿用原日期的参考汇率。

## 支持的结单与解析规则

当前针对用户提供的 **HSBC Pulse UnionPay 双币信用卡英文文字版电子结单**：

- 根据 PDF 文字坐标还原行和列，不依赖文字流的先后顺序。
- 识别 HKD 和 RMB/CNY 子账户、结单日期、入账日期、交易日期、描述、金额、CR、跨页及跨年日期。
- CR 或负金额为入账；PAYMENT / AUTOPAY 入账归为还款，其余归为退款 / 入账。费用由关键词分类；分类不改变金额或方向。
- 保留钱包标识等续行说明。积分、付款示例、宣传、上期结欠、结单余额和汇总不计为交易。
- 按子账户校验 `上期结欠 + 支出 - 入账 = 本期结欠`，缺失字段或差额出现在解析报告。核对一致只是校验线索，不保证所有其他版式都能正确解析。
- 文字扫描件、图片、其他银行及未适配版式会给出错误或警告，暂不提供 OCR，不会伪造交易或以示例数据替代失败结果。
- 单份最多 25 MB、200 页；页面最多 20 份，合计最多 100 MB。

## 重复导入

按账户、币种、结单日、两种日期、原始描述、金额、收支和出现次数识别同一结单的重复记录，合并来源。**同一结单内多笔相同日期、商户与金额的交易不会被误删**。不同结单日不自动去重，避免将真实重复消费合并。移除一个文件后，仍由其他文件支持的交易继续保留。

## 隐私与资源

- PDF.js 在浏览器 Web Worker 内读取 PDF；解析逻辑同样在浏览器内执行。没有业务后端、银行 API、上传接口、OCR / AI 服务。
- 公开汇率调用只向固定 Frankfurter 地址请求 HKD/CNY 汇率；不发送文件或个人数据，使用 `credentials: omit` 和 `referrerPolicy: no-referrer`。
- 文件、密码、完整提取文字均不写入 localStorage、sessionStorage、Cookie 或服务端；页面只保留解析结果和 File 对象。界面只显示账户尾号。
- PDF.js、Worker、CMap、标准字体和 WASM 全部随静态网站提供，不使用第三方 CDN。首次导入时加载解析器，避免拖慢初始页面。
- Vite 配置从已安装的 `pdfjs-dist` 复制静态支持文件到被忽略的 `public/pdf-assets/`，生产构建自动包含这些文件和 PDF.js 许可文件，必须连同 `dist/` 一起部署。
- CSV 防护电子表格公式注入，金额汇总使用整数精确运算，币种独立汇总，不换汇。已下载的 CSV 需要用户自行管理。
- PDF 内的内容均视作数据，不执行内嵌 JavaScript 或其中的指令。界面以 React 文本方式显示文件名、商户和提取原文。
- 用户提供的真实结单及其提取文本不作为仓库样例或测试夹具，临时验证内容仅放在忽略的 `.qa/`。
