# 解析与返现规则

[返回 README](../README.md)

本文记录当前代码的实现口径，不代表银行最新活动条款。返现为估算，最终以银行实发为准。

## 今年返现

交易概览上方显示基础返现、赏世界 5x、PULSE 专属内地奖赏，**全部以人民币显示**。仅计算香港时间本年 1 月 1 日至今天已入账的导入记录，年度返现不受下方交易筛选影响。

尚未入账的交易继续显示在明细中，但不计入任何返现，也不占用两项消费额度；尚未入账的退款同样暂不扣回返现。已入账但支付方式未识别的交易统一按普通消费处理：计入基础返现，以及符合地区和原币种条件的赏世界 5x（封顶前共 2.4%），占用赏世界年度额度，不自动计 PULSE 专属奖赏或占用其额度。相应退款按普通渠道扣回基础及赏世界奖赏；可在详情修正原支付方式或选择仅扣基础返现。交易本身尚未入账时，手动修改支付方式也不会提前计入。

- 基础：人民币和港币净消费的 0.4%，无上限；港币部分用公开 HKD/CNY 参考汇率折算成人民币。还款、费用、奖赏入账本身不计消费。
- 赏世界 5x：按用户指定的非 `HKG HK` 兜底口径估算，未识别为香港的交易默认额外 2%，地区或原币种不明时也计入奖赏及年度额度。明确的香港商户代码（`HK` / `HKG` / `344`）及明确原交易港币不计，可在详情手动修正地区和原币种。优先读取明确商户国家代码，其次读取交易描述或续行末尾的地区代码，支持代码后附带可选原币种及金额，如 `KHM KH USD 6.75`、`VNM VN VND 123,456.00`。不依赖完整国家代码白名单；未知地区仍保留未知状态，不据此推断为内地／澳门或授予 PULSE 专属奖赏。
- 双币结单的 HKD/CNY 是入账币种。海外外币折算为 HKD 入账时，按入账金额及公开 HKD/CNY 汇率估算人民币赏世界奖赏和额度；不会把原交易外币金额当作港币金额。缺少汇率时显示待折算，不能把未折算金额显示成零。当前额度估算沿用每卡每年 CNY 100,000；官方规定为首 HKD 100,000 合资格签账，两者存在汇率差异。
- PULSE 专属：商户地区为中国内地或澳门且有 Apple Pay / UnionPay QR 标记的人民币消费额外 2%，每半年独立消费额度 CNY 80,000，在 1 月 1 日、7 月 1 日刷新。返现金额为今年两个半年累计，进度条为当前半年额度。
- 符合赏世界条件的普通 Tenpay / Alipay / UnionPay 为封顶前 2.4%；符合 PULSE 地区条件的 Apple Pay / 明确银联 QR 为封顶前 4.4%。普通 `UNIONPAY MERCHANT` 不自动当作 QR。
- 两个进度条按**退款前的累计消费**占用额度，退款不会恢复额度。赏世界按 `min(年度合资格消费, 100000) × 2% - 对应退款 × 2%` 估算；PULSE 按 `(min(上半年专属消费, 80000) + min(下半年专属消费, 80000)) × 2% - 专属渠道退款 × 2%` 估算，最低为 0。跨半年退款扣回今年累计奖赏，不恢复任何期间的消费额度。基础按退款后的净消费计算。
- 主卡、每张副卡分别计算三项返现及封顶额度；主卡卡片在前，副卡卡片依次显示在下方。结单内通过卡号和持卡人分段识别实际用卡，跨页继续归属上一张卡；同一账单账户仍合并核对结欠。明确且唯一的同名主副币种卡号可归入同张副卡，同一币种下同名的两张不同卡不会合并。
- 退款无法可靠关联原消费时会提示核对，可在交易详情手动确认支付方式；若退款对应的原消费已超额且未获额外奖赏，可勾选“仅扣基础返现”。专属渠道退款会扣回两项额外奖赏，普通渠道退款只扣回赏世界奖赏。
- 手动修正仅存在页面内存中，立即更新年度卡片；刷新或清除后重置。缺少月份、无法识别的渠道、跨年退款和银行取整方式可能影响估算，最终以银行实发为准。

汇率使用 [Frankfurter 公开日参考汇率 API](https://frankfurter.dev/)：`GET https://api.frankfurter.dev/v2/rate/HKD/CNY`，界面显示汇率日期并支持刷新。请求不含账户、交易、PDF、Cookie 或授权信息。失败不使用虚构汇率；没有可用汇率时港币部分暂不折算，人民币奖赏及额度继续计算。刷新失败且已有汇率时，会明确标注沿用原日期的参考汇率。

官方地区及外币资格参考：[汇丰 2026 最红自主奖赏官方常见问题](https://www.hsbc.com.hk/zh-hk/help/faq/credit-cards/rewards/)、[2026 活动详情](https://www.redhotoffers.hsbc.com.hk/sc/rewards/red-hot-rewards-of-your-choice/details)。官网说明按卡组织的国家／地区代码认定，并要求香港以外的外币交易；截至 2026-10-20，查阅结单说明、奖赏 FAQ 及活动详情，未找到完整结单国家代码对照表。本工具采用用户指定的非香港默认计入规则，属于估算兜底，不代表汇丰已确认所有未识别交易的资格。结单中的地区文字只作为估算线索，最终以银联记录和银行认定为准。当前仅处理 HKD/CNY 入账金额，其他入账币种仍提示未纳入；USD、JPY 等原交易币种折算至 HKD 入账的交易可计入。

## 支持的结单与解析规则

当前针对用户提供的 **HSBC Pulse UnionPay 双币信用卡英文文字版电子结单**：

- 根据 PDF 文字坐标还原行和列，不依赖文字流的先后顺序。
- 识别 HKD 和 RMB/CNY 子账户、结单日期、入账日期、交易日期、描述、金额、CR、跨页及跨年日期。
- 识别交易表内的主卡 / 副卡分段，保留实际卡尾号、账单账户尾号及归属；交易列表、子账户筛选及 CSV 可区分副卡。
- CR 或负金额为入账；PAYMENT / AUTOPAY 入账归为还款，其余归为退款 / 入账。费用由关键词分类；分类不改变金额或方向。
- 保留钱包标识等续行说明。积分、付款示例、宣传、上期结欠、结单余额和汇总不计为交易。
- 按子账户校验 `上期结欠 + 支出 - 入账 = 本期结欠`，缺失字段或差额出现在解析报告。核对一致只是校验线索，不保证所有其他版式都能正确解析。
- 文字扫描件、图片、其他银行及未适配版式会给出错误或警告，暂不提供 OCR，不会伪造交易或以示例数据替代失败结果。
- 单份最多 25 MB、200 页；页面最多 20 份，合计最多 100 MB。

## 重复导入

按账户、币种、结单日、两种日期、原始描述、金额、收支和出现次数识别同一结单的重复记录，合并来源。**同一结单内多笔相同日期、商户与金额的交易不会被误删**。不同结单日不自动去重，避免将真实重复消费合并。移除一个文件后，仍由其他文件支持的交易继续保留。

## 隐私与资源

- PDF.js 在浏览器 Web Worker 内读取 PDF；解析逻辑同样在浏览器内执行。没有业务后端、银行 API、上传接口、OCR / AI 服务。
- 公开汇率调用只向固定 Frankfurter 地址请求 HKD/CNY 汇率；不发送文件或个人数据，使用 `credentials: omit` 和 `referrerPolicy: no-referrer`。
- 文件、密码、完整提取文字均不写入 localStorage、sessionStorage、Cookie 或服务端；页面只保留解析结果和 File 对象。界面只显示账户尾号。
- PDF.js、Worker、CMap、标准字体和 WASM 全部随静态网站提供，不使用第三方 CDN。首次导入时加载解析器，避免拖慢初始页面。
- Vite 配置从已安装的 `pdfjs-dist` 复制静态支持文件到被忽略的 `public/pdf-assets/`，生产构建自动包含这些文件和 PDF.js 许可文件，必须连同 `dist/` 一起部署。
- CSV 防护电子表格公式注入，金额汇总使用整数精确运算，币种独立汇总，不换汇。已下载的 CSV 需要用户自行管理。
- PDF 内的内容均视作数据，不执行内嵌 JavaScript 或其中的指令。界面以 React 文本方式显示文件名、商户和提取原文。
- 用户提供的真实结单及其提取文本不作为仓库样例或测试夹具，临时验证内容仅放在忽略的 `.qa/`。
